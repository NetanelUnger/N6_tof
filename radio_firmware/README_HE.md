# עדכון Firmware למודול ST67W611M1

התיקייה הזאת היא מסלול עצמאי ומונחה לעדכון ה־NCP שמספק BLE/Wi‑Fi על
`X-NUCLEO-67W61M1`. היא מקבילה ל־`training`: כל מה שנדרש לעדכון Windows
נמצא בתוך ה־repository, בלי תלות בעותק מקומי של חבילת X‑CUBE.

הגרסה שנדרשת על־ידי היישום היא profile ‏`mission T01`, ‏SDK ‏`2.0.106`.
T01 כולל את מחסנית הרשת בצד ה־NCP ומתאים לדרייבר שהפרויקט מקמפל.

## הפעלה קצרה

לפני הצריבה יש לסגור (לקצר) את **SB31 ו־SB34 בלוח הרדיו**
`X-NUCLEO-67W61M1`, כדי לחבר את UART_RXD/UART_TXD למחבר Arduino.
בפרויקט ה־ToF הם פתוחים בכוונה: תוכנת הגשר של ST משתמשת ב־PD8/PD9,
המשותפים ל־XSHUT/INT של החיישן. נתקו את כל מקורות המתח והסירו או בודדו
את לוח ה־ToF לפני סגירת הגשרים. לאחר סיום הצריבה ושחזור FSBL, נתקו שוב
מתח, פתחו את שני הגשרים והחזירו את חיבורי ה־ToF לפני הפעלת הפרויקט ו־HIL.
ראו UM3449, טבלה 9 (עמוד 19); המספרים מתייחסים ללוח הרדיו בלבד.

1. סגור terminals שמשתמשים ב־ST‑LINK Virtual COM Port.
2. הרץ `00_CHECK.bat`. הוא מתקן אוטומטית הבדלי סיומות שורה בקובצי טקסט רק אם התוצאה תואמת בדיוק ל־SHA‑256 המקורי, ואז מאמת את כל החבילה. אין צורך להוריד או להריץ כלי תיקון בנפרד.
3. הרץ `01_UPDATE_MODULE.bat`, הקלד `UPDATE ST67` ופעל לפי הוראות ה־jumpers.
4. **שלב חובה אחרי העדכון ושחזור FSBL:** נתק את כל מקורות המתח (ST-LINK, CN8 וכל ספק חיצוני) עד שכל הנוריות כבויות. **פתח מחדש גם את SB31 וגם את SB34 בלוח הרדיו — הסר את שני הקצרים שנעשו לצריבה.** רק לאחר ששניהם פתוחים החזר את חיבורי ה־ToF וחבר מתח. אלה גשרי הלחמה, לא ג׳אמפרי BOOT; הודעת PASS אינה בודקת שהם נפתחו.
5. אחרי החזרת החומרה לתצורה זו הרץ `training\10_LOAD_RAM.bat` ואז `training\11_HIL.bat`.
   Stage 11 קורא `radio info`, דורש SDK ‏2.0.106, ובודק בפועל את פרסום ה־BLE.

הסקריפט מבצע את הרצף הבא:

1. במצב DEV ‏(`BOOT0=1-2`, ‏`BOOT1=2-3`) הוא שומר ב־Flash החיצוני host
   bootloader זמני ומאמת אותו.
2. במצב external Flash ‏(`BOOT0=1-2`, ‏`BOOT1=1-2`) הוא צורב את ה־ST67 דרך
   ה־ST‑LINK VCP בעזרת QConn. בדיקת התגובה היא לחיצת היד של QConn לאחר
   אתחול תוכנת הגשר; עצם זיהוי פורט COM אינו בדיקת תגובה של המודול.
   כשאין תשובה, מופיעה **„אין תגובה מהמודול”**, אין ניסיון צריבה נוסף,
   והתהליך עובר לניסיון שחזור FSBL. כשל אחר מקבל retry יחיד ומוגבל.
3. גם במקרה של כשל, בלוק `finally` מבקש לחזור ל־DEV ומנסה להחזיר ולאמת את
   ה־FSBL. אם `FlashImages/N6_FSBL-trusted.bin` קיים הוא מוחזר; אחרת מוחזר
   FSBL הייחוס של ST כדי שהלוח לא יישאר עם ה־host הזמני.

ה־BAT מציג כשל מסודר (`ST67 UPDATE FAIL`) ומחזיר קוד יציאה שאינו אפס,
במקום להציג מחסנית שגיאת PowerShell. תוצאת השחזור מוצגת בנפרד; כשל
בשחזור אינו מוסתר על ידי הודעת היעדר תגובה. לוג לכל ניסיון QConn נשמר
בסביבת העבודה. רק `ST67 UPDATE PASS` מאשר את סיום העדכון בהצלחה; לאחר
החזרת החומרה לתצורת הפרויקט, בדקו גרסה חיה ופרסום BLE באמצעות HIL.

## אם בדיקת החבילה נכשלת

בהורדת ZIP או ב־Git עלולים להשתנות סופי שורות (LF/CRLF). הכלי הכלול
`Repair-ST67PackageLineEndings.ps1` מופעל אוטומטית מתוך הבדיקה. הוא משנה
רק קובצי טקסט מוכרים ורק אם סיומות השורה לבדן מסבירות את ההבדל ב־hash.
ה־manifest, קובצי הקושחה והתוכנות אינם משתנים. אין צורך בכרטיס מחובר.
המתינו להודעה `Package PASS: SDK 2.0.106, profile t01`.
אם נשארת שגיאת hash, שחזרו את הקובץ מעותק נקי של אותה גרסת פרויקט;
אין לעקוף את הבדיקה או לעדכן את ה־hash כדי לקבל PASS.

גם `01_UPDATE_MODULE.bat` מפעיל כעת את תיקון סיומות השורה לפני בדיקותיו.
לאחר האישור נוצרת עבור QConn סביבת עבודה נפרדת ומאומתת מתחת
ל־`.local-dependencies/st67-updates`. כלי QConn וקובצי הקושחה מועתקים אליה,
וכל הרצה מקבלת עותק חדש. כך שינויי הגדרות וקבצים ש־QConn יוצר אינם משנים
את `radio_firmware/vendor` ואינם מכשילים את ההרצה הבאה. נתיב סביבת העבודה
מודפס והקבצים נשמרים לצורך אבחון גם אחרי כשל. שינוי זה אינו פותר כשלעצמו
שגיאת `CHIP IMG LOAD SHAKEHAND FAIL` בחיבור לחומרה.

## מעגל חדש לחלוטין

במעגל חדש אין עדיין שרשרת boot של הפרויקט, ולכן הסדר הוא:

1. `training\00_SETUP.bat` להתקנת סביבת המחשב.
2. `radio_firmware\00_CHECK.bat`.
3. `radio_firmware\01_UPDATE_MODULE.bat` לעדכון ה־ST67. בסיום העדכון ושחזור FSBL, נתק את כל מקורות המתח, פתח מחדש את **SB31 וגם SB34** בלוח הרדיו ורק אז החזר את ה־ToF וחבר מתח.
4. `training\13_FACTORY_PROVISION.bat` למחיקה מלאה ולכתיבת FSBL, Secure,
   Slot A ושני עותקי metadata.
5. לאחר boot מוצלח אפשר להשתמש בלולאה הרגילה
   `10_LOAD_RAM.bat` → `11_HIL.bat` → `12_FLASH_RELEASE.bat`.

`10_LOAD_RAM.bat` לבדו אינו provisioning למעגל ריק: הוא נעזר ב־FSBL שכבר
מותקן כדי לבצע handoff מאובטח ל־Secure ול־Non‑Secure שב־SRAM.

## אזהרות ורישוי

- קובץ ה־NCP הוא binary חתום של ST. לפי כלי הייחוס של ST, צריבתו עלולה לנעול
  לצמיתות מודול שעדיין אינו נעול. לכן נדרש האישור המדויק `UPDATE ST67`.
- תהליך העדכון מחליף זמנית את ה־FSBL ב־NOR החיצוני. אין לנתק מתח בזמן כתיבה.
- הקבצים תחת `vendor` מקורם ב־X‑CUBE‑ST67W61. תנאי ההפצה נמצאים ב־
  `vendor/LICENSE_BINARIES`, והודעות QConn ב־`vendor/NOTICE_QConn_Tools.txt`.
- `01_UPDATE_MODULE.bat` אינו מפעיל Wi‑Fi באפליקציה. הדגל
  `APP_ST67W6X_WIFI_SERVICES_ENABLED` עדיין קובע אם Stage 11 יריץ גם בדיקת
  station ו־scan; BLE נבדק רק כאשר דגל ה־BLE פעיל.
