# הפעלת דמו N6 — 13 באוקטובר 2026

## מוכנות לבוקר לאחר בדיקת שעה

בדיקת BLE בלבד עברה **3600.546 שניות**: 6,920 תוצאות NPU אמיתיות,
3,673 תמונות CRC תקינות ו־5,971 תשובות CLI. זמן תגובה מרבי219.73ms;
פער קבלה מרבי NPU0.570s ותמונה1.023s, ללא שגיאות או התאוששות חדשה.
הכלי תוקן כדי שכתיבת דוחות לא תחסום BLE; השעה הקודמת עם פערי קבלה
ארוכים נשמרת כלא מאושרת לרציפות. ההגדרות והקושחה אומתו שוב, והנעילה
וכל ידיות החומרה שוחררו. הכרטיס מפרסם, מנותק, ToF מתקדם ויעד התמונה NONE.

**קושחת הדמו נמצאת ב־RAM ואינה שורדת אובדן מתח. אין לבצע Reset לצורך הפעלה.**
שומרים על מתח וחיבור הכרטיס. אם היה ניתוק מתח או Reset, לא מניחים שהקוד
המוגן עדיין רץ: מאמתים מצב ומשתמשים רק בתהליך טעינת SRAM המוגן בהמשך,
עם בעלות בלעדית ו־ELF5689348E...; אין לטעון Debug רגיל או לבצע Flash.

1. מוודאים שאין בודק פעיל, נעילה או לקוח BLE אחר. קובץ הסטטוס המעודכן הוא
   `.local-dependencies/diagnostics/coordinated-owner-progress.json`.
2. פותחים ב־Chrome את [מסוף האתר בשרת](https://natilab-n6-h6bjh2ffbadtfyaw.israelcentral-01.azurewebsites.net/terminal).
   בוחרים `N6-MAINT-B8FB` מתוך הדפדפן. **אין לבצע PAIR ב־Windows**;
   מבטלים חלון pairing של המערכת ולא מוחקים cache/bond.
3. מפעילים `NPU RPS TX` לתוצאות המודל. מפעילים `TOF IMAGE TX` ו־`MAP ON`
   לתמונות. בודקים שהפריימים והרצות המודל מתקדמים ושה־CLI מחזיר PONG וסיום תקין.
4. ציון המודל אינו הסתברות נכונות מכוילת. תוצאה מפריים אחר מוצגת בנפרד.
   אם היא אינה טרייה או שהקישור נותק, אין להתייחס לתוצאה הקודמת כעדכנית.
5. אם החיבור נכשל, שומרים את השגיאה ומתאמים בדיקה; אין לבצע Pair, שינוי
   זהות, מחיקת cache, פקודת credentials או Reset של NCP בריא כפתרון.

האתר עצמו נפרס ותוכנו בשרת אומת. אין כלי דפדפן זמין לבדיקת תצוגה עצמאית
מול הכרטיס באתר השרת; ההוכחה הנוכחית היא מקלט BLE מקומי ובדיקות parser.
קבלת שעה אינה הבטחת עבודה כל הלילה ואינה קבלת Wi-Fi/Cloud/fulltask4.

לבדיקה עתידית, לאחר אימות הקושחה המוגנת ובעלות בלעדית:

```powershell
.\hil_tests\.venv\Scripts\python.exe .\hil_tests\run_ble_npu_soak.py --owner-thread demo-20261013 --duration 3600 --label ble-npu-hour-demo-20261013
```

יש להחזיק קודם את הנעילה באותו `owner-thread`, ולבחור label חדש שלא קיים.
הכלי משתמש ב־pair=False ואינו טוען קושחה או משנה הגדרות רשת/Cloud.

## חיבור לדפדפן

**אין לבצע PAIR לכרטיס N6 ב־Windows.** משתמשים בבחירת ההתקן בדפדפן
ובחיבור GATT בלבד. אין למחוק bond/cache, לשנות זהות או להתגבר על חסימת
גישה. כל כלי אוטומטי חייב להשתמש ב־`pair=False`. מבטלים חלון pairing
של מערכת ההפעלה. חיבור Cloud השמור הוא עניין נפרד ואין לשנות אותו.

1. מוודאים שבעל הבדיקה סיים ושחרר את הנעילה והידיות. כרגע הבדיקה
   הסתיימה והנעילה שוחררה; בכל הפעלה חדשה בודקים `.local-dependencies/diagnostics/coordinated-owner-progress.json`
   ומצב `n6-hardware-owner.json`. אין לקחת בעלות ממשתמש או בודק פעיל.
2. פותחים את מסוף האתר בשרת ב־Chrome ובוחרים `N6-MAINT-B8FB`.
3. מפעילים `NPU RPS TX` לקבלת תוצאות Neural-ART בפועל. הפעלה זו אינה
   בוחרת יעד תמונה. UUID0005 נוסף בסוף DEBUG service0101/index2.
4. מפעילים `TOF IMAGE TX` ובוחרים `MAP ON` לתמונות BLE. מנטרים CRC
   ותשובות CLI. חיבור CLI לבדו אינו מבקש תמונות.
5. ציון המודל אינו הסתברות נכונות מכוילת. רק פריימים בעלי מספר זהה
   מוצגים כתואמים; תוצאה מפריים אחר מוצגת בנפרד. התוצאות נעלמות כשאינן טריות.
6. אם ההתקן או UUID0005 אינם זמינים, שומרים את הודעת השגיאה ומתאמים
   בדיקה. אין לבצע PAIR, מחיקת cache או החלפת זהות כפתרון.

## בדיקות USB לפני הצגה

לא מבצעים Reset: הקוד החי נמצא ב־RAM. לאחר שחרור בעל הבדיקה אפשר
להשתמש ב־COM8 לקריאה ובדיקת `debug ping demo-start`, `tof status`,
`rps status`. מצפים ל־PONG, ToF מתקדם ו־NPU ready/errors0.
`MAP ON SCREEN` הוא יעד תצוגה מקומי. אין לשלוח `wifi disconnect`,
`cloud disable`, פקודת pairing או setters להגדרות NCP: הם מחוץ לפרופיל
השומר על נתונים ועלולים לשנות את המצב השמור.
