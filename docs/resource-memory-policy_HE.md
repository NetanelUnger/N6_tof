# מדיניות מרווחי זיכרון ודיאגנוסטיקה — 23.10.2026

היישום בענף `feature/n6-xip-ota-usb` בלבד, בפרופיל הבדיקה
`Tools/Build-Xip.ps1 -ResourceDiagnostics`. הוא נבנה ונבדק במחשב; עדיין אינו
פעיל על הלוח. הפרופיל הרגיל נשמר כדי לא לשנות בשקט את תמונת השחזור ואת תקציב
ה־RAM הוותיק. מצב הלוח האחרון: A23 מאושרת אך נתקעה ב־STKOF במהלך OTA;
B24 חלקית ואין הבטחה לתמונת fallback תקינה ב־B. אין לבצע פעולה פיזית נוספת
בלי תיאום לפי [מדריך ההתאוששות](xip-recovery-after-a23_HE.md).

## כלל הקבלה

הקיבולת חייבת להיות לפחות 110% מהצריכה המרבית המאומתת, עם עיגול ליישור
הנדרש. למחסנית יש לכלול שרשרת קריאות מצטברת, callbacks, הקשר RTOS ופסיקות
היכולות להיערם. גודל frame של פונקציה יחידה אינו מדידת high-water.
אם הצריכה אינה ידועה, ההקצאה הזמנית היא
`align64(ceil(1.10 * (legacy_envelope + 208 + 128)))`.
208 בתים הם תקציב הקשר שמרני זמני ו־128 בתים נוספים לאי־ודאות; אלה אינם
הוכחה לחסם פסיקות אוניברסלי. אם ניתוח שרשרת או מדידה נותנים ערך גדול יותר,
יש להחליף את המעטפת בערך הגדול ולתקצב גם קינון רלוונטי. ללא מדידה אין אישור
שהמרווח מספיק. גבולות גודל ואריתמטיקת הכפלה נבדקים לפני הקצאה/יישור.

| משאב | מעטפת קודמת, בתים | פרופיל בדיקה, בתים |
|---|---:|---:|
| Main | 98304 | 108544 |
| Radio / Cloud, כל אחד | 8192 | 9408 |
| USB CLI / WiFi control, כל אחד | 6144 | 7168 |
| ToF acquisition | 16384 | 18432 |
| Display | 4096 | 4928 |
| UART / UART test, כל אחד | 3072 | 3776 |
| Update confirmation / NS MSP, כל אחד | 2048 | 2624 |
| USBX control | 16384 | 18432 |
| SPI worker | 768 | 1536 |

ל־SPI נבחרה קודם מעטפת 1024, ואז הוחל הכלל פעם אחת בשכבת FreeRTOS/ThreadX.
הגדלת המחסנית אינה תיקון לנתיב הלוג שנכשל: עיצוב המחרוזת הוצא מה־SPI כבר ב־B25.
ב־A23 שרשרת formatter ממשית דרשה לפחות 776 בתים מול 768 שהוקצו, עוד לפני
תקורות נוספות. בפרופיל החדש גם מדידת PSP מוסיפה קריאות; אין להשתמש ב־128
בתים שנמדדו לנתיב המקומי הישן כחסם לכל השרשרת החדשה.

APP pool בפרופיל הוא 176KiB, USBX pool הוא 64KiB, USBPD pool הוא 18048 בתים.
מחסנית WiFi control והטבלאות החדשות נמצאות באזור NS קיים `.app_shared_bss`;
אין הרחבת הרשאות MPU/TrustZone או שינוי ABI של Secure. Radio pool נשאר 64KiB.
הקיבולות הן provisioning לפני מדידה, לא הבטחת הצלחת כל הקצאה או היעדר fragmentation.

## מה מנוטר ומה אינו מנוטר

המיפוי החוזר הוא `Tools/resource_inventory.py` והתוצאה
[resource-inventory-20261023.json](resource-inventory-20261023.json):
94 הגדרות מאקרו, 568 הצהרות מערכים, 359 מופעי API ו־13 קובצי פרויקט עם מעטפות
ניטור. הספירה לקסיקלית וכוללת prototypes ותנאי קומפילציה; אינה מספר המשאבים
הפעילים או מלאי ממצה של ספריות בינאריות.

בשכבות הפרויקט: כשלי malloc/calloc/realloc, ThreadX byte/block allocation,
enqueue, יצירת thread/queue/pool/mutex/semaphore/event, event-set ושחרור
נרשמים עם סטטוס מקורי, מספר שורה, גודל/ארגומנט, כתובת ומועד. return values
אינם משתנים. realloc שנכשל אינו מוחק את המצביע המקורי. חישובי גודל תורים,
עומק מחסנית והזזת `_sbrk` מוגנים מפני overflow/underflow. נתיבי ספק העוברים
ב־FreeRTOS shim מכוסים שם. לא שונתה ספריית transform של ST.

חריגים מפורשים:

- Secure ו־FSBL ממופים אך המחסניות/allocators שלהם לא שונו בפרופיל NS זה.
- הקצאות פנימיות של ספריות בינאריות NPU/USBPD/newlib אינן מקבלות כולן סיבת
  כשל ברמת הקריאה. `_sbrk` מספק כשל/frontier בלבד, ולא free או largest-block של malloc.
- גדלי פרוטוקול, DMA, תמונה וטנזורים קבועים אינם גדלים שרירותית ב־10%.
  יש לבדוק burst/backpressure ומרווח על סמך שימוש מאומת. תור free-list מלא
  במנוחה הוא מצב בריא; לכן אין אזעקת 10% אוטומטית לכל תור כזה.
- אין כאן זיהוי כל כתיבה שרירותית מעבר למערך או טיפול מלא בכל HardwareFault.
  לאחר פגיעה במחסנית/זיכרון אי אפשר להבטיח printf, תור לוג תקין או המשך ביצוע.
  מוני האבחון נדיפים; אין הבטחת שימור לאחר reset או ניתוק מתח.

## מסלול הדיווח

לכידה שומרת סקלרים בטבלה סטטית, במקטע IRQ קצר עם שחזור PRIMASK.
אין הקצאה, formatting, שליחה לתור או I/O בתוך הלכידה, ISR או SPI.
הספירה רוויה ב־UINT32_MAX והדגל מציין saturation; נשמרת סיבה אחרונה לכל
זוג מודול/סוג, ולא היסטוריה של כל אירוע. הדיווח מתבצע רק במשימת UART,
עם encoder hex קבוע ומאגר 96 בתים, ניסיון אחד לכל שנייה גם בכישלון.
כשל לוג אינו מאפס מונים או מאשר דיווח; ניסיון מאוחר יכול לדווח את הספירה.
guard מונע כניסה חוזרת. empty-poll צפוי נספר בנפרד ללא הצפת הדפסות.

רשומת `[RESOURCE]` של כשל מכילה תשעה שדות hex של 32 ביט:
`module kind count status line argument object tick flags` (94 בתים כולל CRLF).
מודולים: CORE=0, RTOS=1, USB=2, TOF=3, CLOUD=4, RADIO=5, LOG=6, INIT=7.
סוגים: ALLOC=0, ENQUEUE=1, CREATE=2, INVALID=3, OVERFLOW=4, RELEASE=5,
MARGIN=6, WAIT=7, POLL=8. flags: ISR=1, saturation=2.

`debug resources` מבקש דוח שימוש נדחה, ללא איפוס. רשומת שימוש מכילה:
`255 256+kind observations capacity peak minimum_free object flags`.
kind: queue=0, pool=1, stack=2. קיימים 32 מקומות לתורים, 8 ל־pools ו־24
למחסניות; גלישת הטבלה עצמה נספרת. flags=4 הוא stack sample, flags=8 הוא
C heap frontier. דגימת PSP היא מקסימום של דגימות בלבד, אינה watermark של כל
המחסנית ואינה worst-case. שימוש חוזר בכתובת יכול לשמר שיא היסטורי שמרני.
נתוני pool/queue נצפים בנקודות המעטפת בלבד. עדיפות לכשלים יכולה לדחות דוח
שימוש בעומס כשלים מתמשך; הנתונים נשארים בטבלאות ואינם תלויים בתור הלוג.

## בדיקות והשלמה בחומרה

שתי בדיקות native מריצות את קוד ה־C בפועל: הזרקת כשלי alloc/enqueue/create/
release, integer overflow, ISR posture, saturation, טבלה מלאה, logger מלא,
כניסה חוזרת מה־sink, מגבלת שורה וקצב, נתוני pool/queue/PSP וגבולות heap;
וכן `xQueueCreate` עם גדלים קיצוניים, ניקוי control block בהקצאה חלקית וגודל
תקין מדויק. ארטיפקטים נשמרים ללא מחיקה כפויה. בדיקת import חסומה לחומרה
מגינה גם על כלי המיפוי. בניות RAM רגילה ו־XIP בפרופיל הן בדיקות קישור בלבד.

לאחר התאוששות: תחילה קריאת metadata וגיבוי נוכחי, ואז תיקון B במנגנון החתום.
יש למדוד את כל המחסניות תחת NPU/ToF/USB/BLE/OTA ועומס לוג, להשלים ניתוח
call-chain ופסיקות, לבדוק מרווח לפחות 10%, pool minimum/largest request,
תורים תחת burst, כשלי enqueue/allocation ולוג מלא ללא אובדן סיבת כשל.
יש לחזור על HIL100, USB מלא ו־OTA, כולל הוכחת resume אחרי SUSP אמיתי,
עם deadline DMA המקורי וללא העלאת דגימות חיישן לענן. הצלחת העברה ללא SUSP
אינה הוכחת תיקון מנגנון החידוש. תוצאות החומרה האלה עדיין חסרות.
